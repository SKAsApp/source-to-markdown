# Source to Markdown for AI Chat – A Tool for Aggregating  Source Code into A Markdown File for AI Chatbots

[日本語版](./README.md)

`source-to-markdown` is a .NET console application that aggregates source code and configuration files from a specified directory into a single Markdown file, making it easier to pass them to chat-based, web UI-driven generative AI tools such as Microsoft 365 Copilot.

This eliminates the need to upload multiple files individually, allowing you to attach the entire project’s code, including its directory structure. Furthermore, you can restore the repository’s directories and files from the Markdown generated by this tool.


## Features

- Recursively scans the contents of a specified directory
- Consolidates target files into a single file as Markdown code blocks
- Manage the mapping between file extensions and language hints in a JSON file
- Text files for which no language hint has been registered are also output as code blocks with no language specified
- Also supports files without file extensions
- Supports exclusion based on `.gitignore`
- Supports the following default exclusion directories
    - `bin`
    - `obj`
    - `lib`
    - `node_modules`
    - `dist`
    - `build`
    - `.git`
- Excludes hidden files and directories
- Does not follow symbolic links
- Does not include the output Markdown file itself
- Supports reading UTF-8, UTF-8 with BOM, Shift-JIS and UTF-16 LE
- Normalises line breaks to Line Feed（LF）
- Avoids code fence conflicts (when ``` is present in source code, changes the start of the code block to ~~~)
- Restoring directories from Markdown using `--reverse`
- Preventing path traversal, duplicate paths and output under symbolic links during restoration
- Logs output to a file
- Supports the same code on macOS, Linux and Windows


## System Requirements

- OS: macOS, Linux, Windows
- .NET SDK 10 (if building)


## Installation

### Option 1: Pre-built binaries (recommended)

Download the file for your operating system from [Release](https://github.com/SKAsApp/source-to-markdown/releases) and extract it to a location of your choice.

### Option2: Building from source

Clone the repository.

```sh
git clone https://github.com/SKAsApp/source-to-markdown.git
cd ./source-to-markdown
```

Build the project.

For macOS Apple Silicon:

```sh
dotnet publish "./source-to-markdown.csproj" --configuration "Release" --runtime "osx-arm64"
```

For Linux ARM64:

```sh
dotnet publish "./source-to-markdown.csproj" --configuration "Release" --runtime "linux-arm64"
```

For Windows AMD64:

```powershell
dotnet.exe publish ".\source-to-markdown.csproj" --configuration "Release" --runtime "win-x64"
```


## Usage

### Normal Mode

Creates Markdown files from the specified directory.

For macOS and Linux:

```sh
source-to-markdown <source-directory> <output-markdown> [options]
```

For Windows:

```powershell
# Prevent garbled characters in console output
[Console]::OutputEncoding = [System.Text.Encoding]::GetEncoding("utf-8")
# Run
source-to-markdown.exe <source-directory> <output-markdown> [options]
```

Example:

```sh
source-to-markdown ./src ./output.md --force
```

An example of consolidating the entire current directory into `project.md`.

```sh
source-to-markdown ./ ./project.md --force
```

### Reverse Mode

Restores directories and files from the Markdown output generated by this tool.

For macOS and Linux:

```sh
source-to-markdown <input-markdown> <output-directory> --reverse [options]
```

For Windows:

```powershell
source-to-markdown.exe <input-markdown> <output-directory> --reverse [options]
```

Example:

```sh
source-to-markdown ./project.md ./restored-project --reverse
```

If a file already exists in the destination directory, the entire process will be aborted before writing to the file, unless `--force` is specified. To overwrite existing files in bulk, run the command as follows:

```sh
source-to-markdown ./project.md ./restored-project --reverse --force
```


## Options

| Option | Normal mode | Reverse mode | Description |
| --- | --- | --- | --- |
| `--reverse` | Mode switch | Required | Restores a directory from Markdown. |
| `--language-map <path>` | Available | Not available | Specifies a JSON file mapping file extensions to language hints. Specifying this in reverse mode will result in a command-line error. |
| `--verbose` | Available | Available | Displays details such as items being processed, reasons for skipping, and restored files. |
| `--force` | Supported | Supported | In normal mode, overwrites the output Markdown; in reverse mode, overwrites existing files in the destination directory without prompting. |
| `--help` | Supported | Supported | Displays help. |

Undefined options, missing or excess positional arguments, or a missing value for `--language-map` will result in an argument error.


## Format of the Output Markdown

The output Markdown will be in the following format.

~~~markdown
# ./src

`Program.cs`

```csharp
Console.WriteLine(‘Hello’);
```

---

`settings/appsettings.json`

```json
{
  "example": true
}
```

---

`settings/custom-setting`

```
Settings for custom formats
```

~~~

`---` is output as a separator between files.

Language hints are applied to file extensions registered in the language hint settings, such as `csharp` and `json`. Files with extensions not registered in the settings, or those without an extension, will be output as code blocks without language hints, provided the text is in a supported character encoding.

If the body contains a sequence of three backquotes, the fence is switched to a tilde fence. If the body also contains a tilde of the same length, the fence is extended to a length that avoids a collision.


## Reverse Mode Recovery Specifications

- Only file blocks recognised by this tool as valid Markdown will be restored.
- Unrecognised Markdown elements—such as headings, descriptions, horizontal separators and standalone code blocks—will be ignored.
- Relative paths and filenames specified in the Markdown will be used.
- Even for code blocks without language hints, file extensions will not be added or altered.
- Restored files will be in UTF-8 encoding without a Byte Order Mark (BOM).
- The line break character in the restored files is Line Feed (LF).
- As the original file’s character encoding, BOM and line break format are not preserved in Markdown, the restored files may not match the original byte sequence.
- Absolute paths, paths pointing outside the restoration destination, duplicate paths, and paths where files and directories conflict are rejected.
- Files will not be written under symbolic links leading outside the restoration destination.
- If even a single invalid path is found, the entire process will be aborted before the restored files are written.
- If even a single existing file is present and `--force` has not been specified, the entire process will be aborted before the restored files are written.


## Language Hint Configuration

The mapping between file extensions and language hints is managed in `appsettings.language-map.json`.

Example:

```json
[
	{
		"extension": "cs",
		"fileType": "csharp"
	},
	{
		"extension": "csproj",
		"fileType": "xml"
	},
	{
		"extension": "json",
		"fileType": "json"
	},
	{
		"extension": "md",
		"fileType": "markdown"
	}
]
```

If you wish to use your own language hint JSON file, specify the `--language-map` option.

```sh
source-to-markdown ./src ./output.md --language-map ./my-language-map.json
```

Language hint settings are used solely for the display of Markdown code blocks. They do not constitute a list for excluding file extensions not included in the settings.


## Supported Character Encodings and Text Detection

The following character encodings can be read.

- UTF-8
- UTF-8 with BOM
- Shift-JIS
- UTF-16 Little Endian (LE)

Empty files are treated as text files. Files for which the character encoding cannot be determined, files that may be binary, and files larger than 50 MB are skipped and logged as warnings.


## Exclusion Rules

The following items are excluded from the output.

- Files or directories matching `.gitignore`
- Files or directories within the default exclusion directory
- Hidden files
- Files or directories within hidden directories
- Symbolic links
- The Markdown file itself
- Files with an unrecognised character encoding
- Files identified as binary
- Files larger than 50 MB

For files excluded by default, only the total number is displayed as `Number of files excluded by default` upon completion of processing. When `--verbose` is specified, you can view the files excluded by default and the reasons for their exclusion.


## Logging Configuration

Serilog is used for logging. By default, logs with a level of `Information` or higher are written to a file. The configuration file is `appsettings.json`.

Example:

```json
{
	"logging":
	{
		"logDirectoryPath": null,
		"minimumLevel": "Information",
		"retainedFileCountLimit": 31
	}
}

```

### Configuration Options

| Option | Description |
| --- | --- |
| `logging.logDirectoryPath` | The destination directory for log files. If set to `null`, a `log` directory will be created in the directory where the executable file is located. |
| `logging.minimumLevel` | The minimum log level. The default is `Information`. |
| `logging.retainedFileCountLimit` | The number of log files to retain. The default is `31`. |

Log file names follow a daily rolling format.

```text
source-to-markdown-YYYYMMDD.log
```


## Exit Codes

| Exit code | Meaning |
| ---: | --- |

| `1` | Argument or pre-validation error |
| `2` | Runtime error |

## Important Notes

- If the input directory contains sensitive information, please ensure you check the contents before sharing the output Markdown.
- This tool does not perform source code analysis or mask confidential information.
- Please use the reverse mode only on Markdown you trust. Although safety checks are performed, please verify the output destination and input content before restoring the data.
- The Markdown format cannot fully preserve the original character encoding, BOM, line break format, file attributes or execution permissions.
